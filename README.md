# Migo · 觅购

**Find what fits. Buy with confidence.**

Migo 是一个购物 Agent 项目：理解需求、比较商品、分析评论，再由用户确认授权并完成模拟购买。当前可运行的首个场景是耳机；其他品类是后续扩展方向，尚未实现。

A shopping agent for finding suitable products and making informed purchase decisions. The current working demo focuses on headphones, with explicit user authorization and simulated checkout. Additional categories are planned.

本仓库由 HeNingrui 整理和维护，基于 HackU-Naai_Lung 团队协作成果；原团队说明保存在 README.team-original.md，A/B/C/D 模块及公共接口沿用现有实现。

本版把队友的对话与交易主线、B 的搜索排序、D 的 40 件商品和 400 条评论接入同一份 SQLite。可以从需求搜索走到授权、模拟付款及保存凭证。币种 HKD，付款在本地模拟。

## 启动

Windows 安装 **Python 3.12 或更新版本**，右键 ZIP 选择**全部解压**，进入解压后的项目文件夹，再双击 **Start.cmd**。不要在压缩包窗口里直接点击启动，Windows 可能只临时解压启动文件，导致找不到 scripts/run_demo.py。

首次启动创建 `.venv` 并安装团队 `requirements.lock.txt` 中的依赖，需要联网。之后默认本地规则解析，无需 API key，可离线演示。

地址：**<http://127.0.0.1:8768/>**。启动窗口保持运行，Ctrl+C 停止。端口占用时运行 `Start.cmd --port 8769`。

如果同端口的本项目已在运行，启动器直接打开现有页面，不重复安装或另启服务；其他程序占用端口时会提示换用空闲端口。

已有 Python 环境的队友也可运行：

```text
python -m pip install -r requirements.lock.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8768
```

## 演示操作

1. 输入“我要白色无线耳机，300以内，必须降噪”，或使用右侧条件筛选。后续可以说“只要黑色”“预算改成500”。支持“价格越高越好”“最便宜”明确排序；“换一批”“查看更多”继续取未展示商品，“查看全部商品”一次展示最多 20 件，继续换批可看完全部合格商品，筛选条件与排序保持。
2. 选择商品及数量，查看含运费的报价。默认演示运费 HK$10，首次钱包 HK$5,000。
3. 点击“设置本次购买授权”，阅读金额、数量、商家、地址、有效期、付款方式并确认。
4. 点击“执行这一笔模拟付款”。交易内核最终校验，扣模拟余额和库存，保存订单。预计银行卡回赠不减少付款，也不直接入钱包。
5. 在“交易记录”查看订单、判定、凭证和审计；在“评论与水军分析”查看独立评分及原文依据。

“取消当前选择”取消未执行的选择和报价；“撤销授权”撤销当前权限。已经支付的记录保留，本版未实现真实退款。

## 数据与能力边界

- 40 件商品均为虚构演示商品。品牌、型号、价格、库存、商家描述、设备兼容及配送天数均是演示设定。
- 每件 10 条英文模拟评论，共 400 条。显示星级是**全部评论评分**的平均值，保留一位小数，可疑评论仍计入平均值。
- 水军检测依据极端话术、号召用语、重复措辞。当前开发集的 10 件受影响商品全部找到；70 条协调评论找到 60 条，漏 10 条，正常评论误报 0 条。这是模拟开发集结果，不是现实准确率或付费水军的证明。
- 搜索先遵守明确偏好顺序，再按特征 0.5、价格 0.3、评论 0.2 综合评分。排序使用的筛选后评论分与原始平均星级分开返回。缺评论时不编造默认分。
- 6 件真实京东商品观察及 2 份银行观察单独保存，空值保持未知，不混入可购买的 40 件目录。
- 银行卡试算固定为用户指定的 2026-10-03 京东/HKD 场景，学生资格、登记、志账、月度签账及上限由可修改的演示条件提供。未知条件不按最高回赠作确定推荐。
- 这是本机单个演示用户应用；没有生产账户认证、真实银行核验或真实京东扣款。

## 数据保留及可选模型

运行库默认 `var/demo.sqlite3`。首次初始化与重启均保留已有价格、库存、余额和交易。原 v1 商品库通过加列迁移到 v2，不重新覆盖业务记录。ZIP 不包含运行数据库，首次解压启动得到新的账户。

用环境变量 `DEMO_DB_PATH` 可指定其他数据库。搜索、商品详情、评论、报价、付款和记录都使用这一条路径。

接语言模型时复制 `.env.local.example` 为 `.env`，填自己的模型地址、型号及 key，再设置 `LLM_ENABLED=true`。模型负责理解需求，并结合已筛选商品、不同评分的评论和可疑话术信号解释推荐、回答追问。它只改解释文字，不能更改商品、价格、排序、条件、授权或扣款。模型收到的目录和评论仍明确标为模拟资料。浏览轮通常调用两次 API；按钮操作不调用模型。

页面顶部显示配置的模型、实际返回的模型名及当前服务成功收到 API 响应的次数；每条回答标注是模型分析、数据库回答还是本地规则回退。配置成功不等于每轮都调用成功。网络或格式失败时明确提示回退，保留已经核验的结果。已测试 DeepSeek 真实调用、中文金额解析和同一对话的评论追问；实际接口返回模型名为 `deepseek-flash`，配置名为 `deepseek-chat`。

修改配置后须停止旧启动窗口再运行 Start.cmd，已有服务不会自动读取新配置。`Start.cmd --offline` 可强制使用规则。不要提交 `.env`；交付 ZIP 不含 key。自动测试始终使用 `LLM_ENABLED=false`，避免实际 API 消费。

聊天会话存在当前进程内存，重启需重新开始对话及确认新的授权；钱包、订单和旧授权审计仍保留。“新对话”也不会清理数据库中的旧授权。只运行一个服务进程演示。

仅在明确要清空演示交易时执行 `python scripts/reset_demo.py --db var/demo.sqlite3 --yes`；先备份，保留评论与观察记录。正常启动从不重置。
